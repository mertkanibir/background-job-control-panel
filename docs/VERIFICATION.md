# Verification record

Verified locally on October 12, 2026, with Node v24.21.0 on macOS arm64.

## Engine and HTTP API

`npm test`: **19 tests passed, 0 failed**, including:

- Real text, CSV and SHA-256 worker outputs persisted in SQLite.
- CSV quoted fields and 130,000 rows without argument-stack overflow.
- Exponential retry timing, dead-letter exhaustion and successful manual recovery.
- Durable idempotency and explicit conflicting-payload rejection.
- Paused/scheduled claims, pending cancellation without execution and genuine running-worker termination.
- Concurrent cancellation/manual retry retains the correct active worker.
- Eight CPU jobs obey concurrency 2 and terminal jobs are not reclaimed.
- A child process is killed with SIGKILL while working; the next scheduler records interruption and completes the unfinished job. A previously completed job keeps one attempt.
- A second owner is rejected even when the filesystem lock is removed; settings persist across restart.
- HTTP commands expose stored results, SSE invalidations/reconnects work and foreign origins/non-local hostnames are rejected.

Existing processing, cancellation and recovery assertions remain in place. The optional recorded walkthrough covers navigation, inspection, the native dialog and cancellation of a real live hash chain; `docs/motion-demo.webm` was measured at 3.96 seconds and approximately 1 MB.

## Development story

`npm run dev` starts both the API on 4175 and Vite on 5175. A browser submitted `sku,qty` data through the CSV form. The flow was:

`React form → Vite proxy → Node API → SQLite claim → worker thread → persisted result → SSE → inspector`

Observed responses were 200 for the snapshot/event/detail reads and 201 for enqueue. The persisted and rendered result contained two rows and a quantity sum of 9 for the input `R1,5` / `R2,4`.

## Scope

The checks establish local queue behavior and the browser/API/data path. They do not establish distributed execution, multi-user authorization, production capacity or external-side-effect exactly-once delivery. These are documented limitations, rather than implemented features.
